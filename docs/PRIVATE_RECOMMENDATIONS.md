# Private suggestions and reading bundles

Discover for me now starts with a small bundle: an unread book by an author already explored, a book by an author not yet explored, and a shorter book. When no familiar author fits, the first slot explicitly becomes a general direction. Each slot offers up to four substitutes, and choosing one preserves the other current choices. Duplicate work IDs are excluded and the initial bundle prefers different authors when the available shortlist allows it. The existing discovery filter browser remains below the bundle.

The **Your interests** form saves fields, catalog genres, up to eight topic terms, a short-book page limit, and an optional owned discovery filter. Topic terms match saved titles and tags; they are not inferred interpretations of a book. A saved filter restricts all three slots. If that filter is deleted, the bundle pauses and asks the reader to choose a replacement or explicitly remove the restriction. Its original ID and name remain in the private preference record until that choice is saved.

Within each slot, suggestions prioritize explicit interest matches, author/tag connections to **More like** feedback, membership in bookmarked visible rankings, then wishlist saves. Ties use title and ID. Explanations show the matching fields, genres, terms, connected books or bookmarked list names. With no matching personal signals, the interface calls the results catalog starting points. There are no invented criterion assessments, cross-ranking score comparisons or quality scores. Published source positions and independent editorial orderings remain unchanged. Unranked reading collections are not counted as merit rankings.

Completed current or archived reading attempts are excluded. Current entries with reading progress, a start date, or reading/paused/abandoned/finished status are also excluded from next-book suggestions. Author familiarity considers current and previous reading records; saving a wishlist item alone does not establish familiarity. Anonymous, unknown and generic various-author credits do not establish an author identity. A book with multiple identified authors only qualifies for the new-author slot when none has been explored.

The short-book slot requires a positive recorded page count within the chosen limit. A saved library edition uses its frozen reading basis, including an explicitly unknown length; later catalog enrichment cannot silently change that history. Unsaved works use the current default edition. Python supplies each provisional time estimate and the bundle total. Unknown pages or durations are counted separately, and the interface exposes the edition basis and illustrative time range. Exploring or substituting a bundle does not create library items or planner allocations; the book link opens the existing edition/save/plan flow.

**More like** adds a private author/tag signal. **Not interested** hides that work from suggestions, and **Later · 30 days** hides it until the recorded date. The private feedback panel lists active and expired choices and can clear each signal; a recently changed non-deferred signal also has an Undo action. Clearing retains a neutral revision record, preventing an old browser tab from recreating a stale choice. Preference and feedback writes require the expected revision and run through the mutation receipt guard. A conflict keeps preference drafts visible until the reader explicitly loads the saved version.

The new `RecommendationFeedback` table stores both the one-per-account preferences record and individual work signals. Private JSON/ZIP exports include these rows and saved-filter references. All recommendation endpoints require authentication and use `Cache-Control: private, no-store`. Browser cache entries are scoped by account and invalidated when their underlying preferences, feedback, library/history, bookmarks, filters, catalog or reading pace changes.

Implementation lives in `backend/core/recommendations.py` and `frontend/src/recommendations.tsx`. Response serializers generate the frontend contracts. The focused regression coverage in `backend/core/test_recommendations.py` verifies ownership, actual reasons, source-order preservation, history exclusions, frozen unknown lengths, deferred expiry, revision conflicts, valid substitutions and honest cold starts. Tests use an isolated Django test database; no fixtures belong in the owner's database. Migration, final build and full verification status are recorded in the current handover.

For an owner walkthrough, open Discover for me, save a couple of interests, bookmark a ranking, inspect a suggestion's reasons and time assumptions, substitute a book, try each feedback action, and clear or undo it. A book link should still lead to the existing edition choice and private library/planner actions.
