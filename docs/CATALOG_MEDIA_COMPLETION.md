# Completing catalog covers and portraits

The [later 5 October throughput follow-up](PORTRAIT_SOURCES_2026_10_05.md) adds Wellcome Collection and Nobel portrait sources, supports Wikimedia's new thumbnail host, and distinguishes short MediaWiki maxlag waits from HTTP rate limits. It records actual saved gains and the limited scope of the new sources.

The [5 October coverage correction](PORTRAIT_COVERAGE_FIX_2026_10_05.md) fixes legitimate Open Library image redirects, the philosopher identifier, short-title matching and disambiguation. Portrait lookups reuse saved work-to-author identifiers. `linked-wikidata-portraits` follows corroborated author/Wikidata links as a separate provider. Default batches prioritize the larger portrait backlog: Open Library 60, linked Wikidata 30 and public covers 15. This does not increase HTTP concurrency or bypass cooldowns.

Run from the project directory:

```bash
./scripts/complete_catalog_media.sh --background
```

This starts a detached, resumable process with **no batch limit**. Keep the computer awake and connected to the internet. On macOS, `caffeinate -i ./scripts/complete_catalog_media.sh` instead runs in the foreground and prevents idle sleep while it runs. Closing a foreground terminal stops that foreground process; a background process continues, but neither mode survives a restart. Run the same command again to resume after a restart.

Alternative-source batches receive a soft 60-second lookup budget so a slow source regularly yields to others. The active record finishes before switching, and untouched records remain pending. Setup and the active record can extend the elapsed time. Set `--batch-seconds N` on the runner to change it, or zero to disable it. Status incorporates fresh active-batch saves as well as completed batches.

The runner also measures source yield separately from provider health. After 100 clean lookups without a saved image and at least 60 seconds of measured child runtime, a source gets a sample batch every five minutes. Any saved image restores ordinary rotation, including a checkpointed partial success before a stop. Cheap empty checks alone, provider errors and deferred image downloads do not trigger this scheduling rule. Measurements persist in `source-scheduling.json` and appear under `source_scheduling` in status; no source becomes exhausted solely because of low yield. A real provider cooldown always takes precedence. Historical timings are not inferred.

```bash
./scripts/complete_catalog_media.sh --status
tail -f research/_runs/media-completion/worker.log
./scripts/complete_catalog_media.sh --stop
```

A daily database/media backup precedes writes. Each accepted image is saved immediately. Existing images, personal reading records, notes, ranking orders, page counts and bibliographic verification are preserved. New cover-only display editions explicitly have unverified language/edition metadata.

The runner alternates Open Library/Internet Archive covers, Open Library author photos, cached library/Wikidata identity batches, DBpedia, GND/lobid and Rijksmuseum portraits, Wikipedia book covers, Wikimedia portraits, Wellcome and Nobel portraits, Library of Congress covers/portraits, BnF/Gallica covers/portraits, and targeted publisher covers. Google Books is also supported, but is skipped with `credential_required` unless `GOOGLE_BOOKS_API_KEY` is exported in the runner's environment. Plain commands do not load `.env`. The key is never included in logs or response caches. No paid service is automatically enabled. Goodreads scraping is not implemented or claimed.

Set `MARGINALIA_MEDIA_CONTACT` to an explicitly chosen public contact email or project URL before starting the worker to identify the operator in its User-Agent. Nothing is inferred from the owner's account, Git configuration or local environment. [Open Library](https://openlibrary.org/developers/api) and [Wikimedia](https://www.mediawiki.org/wiki/API:Etiquette) request a useful contact for regular API traffic. Default request spacing remains unchanged; setting contact information does not automatically increase traffic.

The three additional portrait sources have separate durable queues and the same soft 60-second batch budget. DBpedia checks up to ten people's human identities and authored catalog works in one request, then their primary-image credits in one Commons request; verified candidates are checkpointed before downloads. Incomplete SPARQL responses cannot establish identity. GND/lobid connects an exact catalog book's author role to a unique GND authority and its separately licensed depiction, using at most two metadata requests with 2.1-second host spacing. Rijksmuseum connects a verified author QID to a museum portrait's sole depicted person, checks image-specific public-domain rights, and downloads from its independent `iiif.micr.io` host. It shares DBpedia identity discovery; DBpedia and GND portrait bytes still use Wikimedia hosts. See [the source assessment and actual saved results](PORTRAIT_SOURCES_2026_10_05.md#additional-api-assessment-and-integration).

Cover matches require a matching title and credited author. Matching preserves non-Latin text and understands library headings such as `Hugo, Victor, 1802–1885`, accented Latin names and compatible initials. Verified catalog aliases and saved Open Library IDs/valid ISBNs provide discovery hints; remote identity still has to agree. Wikipedia fallback additionally requires a book infobox and a cover/first-edition caption. Open Library portraits require a compatible full author name, a matching catalog work, and an unambiguous author record. Library portraits require corroborating works, authority links or dates associated with the matched subject. Name-only results are withheld.

Open Library name-search fallback checks whether the author record has positive photo IDs before downloading the author's bibliography. The work check remains mandatory when a photo exists; authors without photos no longer cause a needless bibliography request.

Verified positive caches take priority before ordinary batch limits. Compatible positives from the preceding Open Library matching policy are recovered using the exact current item identity, with their author IDs, work matches, credited source and image URLs rechecked. Current negative caches and old audit files are preserved. This recovered 43 older candidate records that the policy change had hidden from download priority.

Alternative portrait providers also get a separate `--cached-only` download pass. It performs no discovery, keeps image retry/host restrictions, and can run while the source's metadata API is paused or being sampled. Separate `*-cached-stats.json` files and `cached_downloads` status entries keep its results from overwriting metadata health. Empty passes wait five minutes; known pending images schedule their own next retry. A successful download restores normal source sampling. The 5 October validation pass saved 24 images in 38.81 seconds using existing matches; that is a measured cached-download batch, not an ongoing discovery benchmark.

`cached-wikidata-portraits` builds an index of existing public library response files once per child process. It requires a unique complete-name match and a reciprocal catalog-work/author link, then checks up to 50 authority IDs in one Wikidata request and retrieves image credits in Commons batches. It sends no new Open Library requests and works even when a catalog edition has no saved library URL. Changed identity URLs reopen affected lookups; missing cached evidence is polled later instead of being marked exhausted. The initial audit found 216 missing people with verified library/Wikidata links but no library photo, including 19 without usable edition links. These are identity opportunities; most image availability remains unverified. Existing Wikidata rate limits still apply.

This source also checkpoints completed people before returning a later Commons outage. Unfinished people stay eligible for discovery; only complete no-image results become negative caches. Per-authority Wikidata checkpoints let regrouped retry batches request only unknown IDs. Their 24-hour freshness inherits the original HTTP response age, and malformed or expired entries are revalidated. Completed candidates remain available to the separate cached download pass while metadata requests wait. Newly ready images schedule that pass promptly using their own queue deadlines, avoiding the five-minute empty-cache poll. A first person whose lookup already completed can download immediately despite a later person's metadata failure. The source's first successful live batch added 25 portraits in 28.99 seconds; this is a measured batch, not a sustained-rate prediction.

Portrait bibliography matching now handles distinctive main titles when a subtitle is omitted, and narrowly recognized series bundles, only with the same full author identity and a reciprocal library author-role link. A publisher-series parenthesis needs explicit matching series metadata; arbitrary parenthetical text is not discarded. Conflicting subtitles, individual volume scope and derivative works remain distinct. These rules corroborate a person's identity and do not change cover/edition matching. Reviewed work aliases flow separately from canonical titles into Wikimedia, Open Library, GND and DBpedia; changed aliases reopen only the affected lookup. The alias registry is currently empty, so this wiring itself is not a claimed coverage gain.

Gallica uses its SRU and IIIF APIs and labels accepted historical bindings, title pages and depictions explicitly. Library of Congress uses its JSON API; an access denial pauses requests instead of bypassing it. Publisher extraction is limited to known source pages and a small number of publisher/ISBN-specific discovery routes, using structured Book metadata with title/author and, when supplied, ISBN agreement. Exact host allowlists, public-address checks, robots rules, redirect checks, bounded downloads and request spacing apply. It is not a general website crawler.

Open Library credits identify the source but do **not** establish a reusable image licence or original photographer; these limitations remain explicit in image attribution. Library/Commons rights metadata and historical-depiction labels are retained. A representative image never establishes a particular edition or page count. Existing selected editions and images are rechecked immediately before each save; a concurrent identity/edition change defers the record for review.

Each provider has a durable queue. Fresh records precede item-level retries; within that group, gaps in shared rankings and collections take priority. Individual matching/download errors have bounded attempts. Provider outages use a separate waiting state and do not consume those attempts. Persisted cooldowns schedule a one-record recovery probe, with exponential delay from 15 minutes up to six hours, while other providers continue. HTTP 200 MediaWiki maxlag uses a separate five-second to five-minute recovery schedule. `Retry-After` can extend either delay, and an existing longer restriction is preserved. A temporary outage does not permanently disable the provider. Missing credentials and worker crashes remain explicit until a deliberate restart.

Temporary HTTP408/500/502/503/504 and network faults now use a distinct recovery schedule: 60, 120, 240, 480, then at most 900 seconds. Actual network success clears that transient failure streak. [Wikimedia's guidance](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits) supports delayed retries and exponential backoff; the worker always preserves a larger server `Retry-After` and any existing longer cooldown. HTTP403/429 access/rate restrictions retain the longer schedule above. Metadata health and host transport both retain the error category across restarts.

The public cover worker now carries provider-specific errors through its per-book audit and batch summary too: temporary failures no longer lose their category and accidentally inherit the generic fifteen-minute minimum. Mixed failures retain the strictest restriction and latest retry deadline. A successful Internet Archive fallback clears the earlier Open Library failure for that book. Cover requests use the shared public-contact/User-Agent configuration.

No-match results are retained, not retried forever. Corrected identity/edition/source inputs reopen affected work automatically. Successful public API responses and verified candidate metadata are cached across batches; unusable images advance through a bounded candidate list without repeating successful discovery. Credentialed response bodies are not cached. Cache expiry alone does not reopen an unchanged terminal queue record. The runner does not bypass rate limits, authentication or access restrictions.

A failed image host does not discard already verified alternatives on another advertised host. Each failed host is attempted at most once per candidate call; original URLs, redirect checks and host cooldowns remain enforced. If no candidate succeeds, the strongest restriction and latest retry time are preserved for that record. In Wikimedia portraits and alternative-source workers, image outages increment `image_deferred` and leave that person's verified candidates queued without pausing healthy metadata services or other image hosts. Metadata outages still pause the provider. Old provider cooldowns remain in force until expiry. Source-health error counters exclude these image deferrals; the per-record audit retains the outage and retry time.

Wikimedia prioritizes cached positive candidates and checks human/image claims before requesting full articles. Intro queries use at most twenty titles, matching the [TextExtracts API limit](https://www.mediawiki.org/wiki/Extension:TextExtracts#API). Full articles retain HTML headings and emphasized titles, allowing short titles and omitted subtitles to be corroborated in an authored bibliography or a publication-date context. Reviews, other-author credits, references, generic title fragments and volume conflicts cannot establish the new short/main-title matches. Article tokens are prepared once and kept within section/block boundaries. An uncorroborated exact-name page gets one bounded occupation-qualified fallback, including when the namesake has no image; it does not trigger a full-article request for an image-less identity.

Discovery completes cheap verified images before difficult full articles and retains completed people if a later request fails. Only completed empty lookups become negative candidate caches. Incomplete people keep their retry budget, and no further discovery starts after an outage. Incomplete HTTP200 payloads can supply valid partial results but are not cached as complete responses; older incomplete cached payloads are revalidated through ordinary throttling. Policy v7 reopens old negatives while retaining compatible positive v6 candidate checkpoints. Cooldowns and original audit records remain intact.

Status `complete` means no missing or unreadable default covers or portraits. `needs_review` means all selected sources are exhausted, need configuration or failed **and records remain unresolved**. `waiting_for_provider` means a timed recovery is pending. `stopped` is an intentional stop; `batch_limit` is only used when the optional verification flag `--max-batches N` was supplied. The default has no such limit. `--status` checks the process lock and reads current catalog/file coverage instead of trusting old counts or a reused PID.

`research/_runs/media-completion/unresolved.json` lists missing IDs, titles/names, ranked priority, file problems and provider outcomes. It updates initially, after every batch and on a normal stop/completion. The inventory verifies image containers and decodes pixels, caching results only while the file signature is unchanged. Broken existing references are reported for review rather than silently replacing an existing selection. Per-image audit JSONL records, `provider-health.json`, cooldowns and status are in the same folder; older Wikimedia portrait details remain in `research/_runs/2026-09-28/portraits/`. Operational queue indexes and HTTP/candidate caches live in `data/enrichment/`. Logs rotate into verified compressed archives. Do not delete the queues to force retries: that discards progress and can repeat the original looping problem.

For a deliberately bounded run, for example:

```bash
./scripts/complete_catalog_media.sh --providers gallica-covers,gallica-portraits --max-batches 2
```

Provider names are `google-covers`, `openlibrary-portraits`, `cached-wikidata-portraits`, `dbpedia-portraits`, `gnd-portraits`, `rijksmuseum-portraits`, `linked-wikidata-portraits`, `wellcome-portraits`, `nobel-portraits`, `wikipedia-covers`, `covers`, `portraits`, `loc-portraits`, `loc-covers`, `gallica-covers`, `gallica-portraits`, and `publisher-covers`. This command performs real, backed-up catalog writes when a safe match is found; it is not a dry run. Run the unrestricted background command afterward to resume all providers.

This runner exhausts supported sources; it cannot guarantee that an identifiable, available portrait or standalone cover exists for every historical person, anonymous contributor, poem, essay, or series. Such records remain explicit review tasks instead of receiving unrelated or generated images.
