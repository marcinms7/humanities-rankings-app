# Frontend request lifecycle

`frontend/src/api.ts` keeps the existing `api`, `all`, and `useResource` interfaces. GET requests share in-flight work and a memory-only, account-scoped cache. There is no localStorage, IndexedDB, service-worker, or HTTP cache of API responses. Changing or ending a session clears retained responses, aborts old requests, and prevents late responses from entering the next account's state. A BroadcastChannel tells other open tabs to recheck their session without sending private payloads.

Ordinary GET responses are fresh for 30 seconds, catalog facets and static curriculum content for five minutes, and operations summaries for 15 seconds. Sessions and exports bypass this cache. Retained successful responses are bounded to 80 entries and approximately 8 MiB of serialized data; oversized responses are delivered without retention. Returning to a visible tab revalidates expired data. Navigation also reuses fresh responses. API requests have a 30-second timeout; mutations are never automatically retried.

`queryPolicies.ts` maps reads and successful mutations to dependency tags. Library changes refresh library, plan, study-state, and discovery reads that depend on those tags, while preserving unrelated catalog facets. Ranking book payloads depend on catalog data, but metadata-only ranking overview cards do not. Study notes invalidate saved study state while retaining static curriculum content. Allocation and edition previews invalidate nothing; confirmed applications invalidate their affected resources.

When adding an endpoint, add its dependencies and mutation rules to `queryPolicies.ts`. The application's `version` remains a notification for preview validity and component synchronization; changing it alone does not discard fresh cached requests. An explicit refresh action should call `queryCache.invalidate` with the relevant tags. Failed requests are not cached, and structured `APIError` objects retain the HTTP status, details, and server request ID.

Major screens load through React lazy imports under a route error boundary. The navigation remains available if a route fails to render or its chunk fails to load. Topbar search state is local to its memoized component, and the app context value is stable across unrelated shell updates.

Saved regression cases are in `frontend/tests/queryCache.test.mjs`. They were added without execution under the owner's current testing preference. When test execution is authorized, run `PATH="$PWD/.node/bin:$PATH" npm --prefix frontend run test:cache`. Routine static checks are `npm --prefix frontend run check`, `npm --prefix frontend run lint`, and `npm --prefix frontend run format:check`; production assets use `npm --prefix frontend run build`. Generated API contracts are excluded from lint and formatting and checked separately with `.venv/bin/python manage.py export_frontend_contracts --check`.
