# Catalog search and browsing navigation

Catalog and author searches now match accent-folded words and prefixes across titles, author names, explicitly recorded alternate names, and catalog tags. All query tokens must match; exact titles and title prefixes precede other matches. Search relevance is a discovery aid and never changes a ranking's merit order. Quotes, operators and punctuation are treated as plain input, with bounded token counts and parameterized queries.

SQLite uses an FTS5 index in `data/search/catalog-<database-identity>.sqlite3`. This is disposable shared-catalog metadata, not another authoritative database. Existing visibility and ownership querysets filter every set of candidate IDs, including searches of archived books still in a reader's library. Private notes, scores, histories and accounts are never indexed.

Rebuild explicitly with `.venv/bin/python manage.py rebuild_search_index`; inspect metadata/freshness with `--check`, or reconcile existing documents with `--sync`. Search requests read the index and may schedule background work; they never rebuild synchronously. Full rebuilding is reserved for that explicit command, initial creation, schema upgrades and damaged-index recovery.

Title, author-name, active-tag and author/tag-membership changes now enqueue only affected identities after a successful catalog commit. A durable disposable `.pending.sqlite3` sidecar deduplicates those identities; it contains no private fields. A worker refreshes the changed book, or an author/tag's dependent books, in one FTS transaction. Individual document fingerprints prevent unchanged rows being rewritten. Images, edition metadata, biographies, reading notes and other unindexed fields enqueue nothing. A queue generation captured before each source snapshot prevents acknowledging another edit that arrives during synchronization, including a second edit to the same book. Rolled-back saves never enqueue work; interrupted updates retain the prior complete index and pending changes.

SQLite database/WAL timestamps still catch bulk/import changes and older running workers that do not emit the new signals. On searches, changed source files trigger reconciliation at a bounded 60-second interval. Five narrow reads compare only searchable catalog columns and links first; unrelated private/image writes therefore cause neither document reconstruction nor FTS changes. If searchable content differs, reconciliation updates only changed document fingerprints. A full source digest is invalidated after incremental FTS updates so a later bulk revert cannot incorrectly appear current. Legacy `.dirty` markers are no longer rebuild triggers.

Search can temporarily read the previous index while background synchronization runs. Pending committed edits older than 120 seconds use the portable fallback; source-only changes use their first observed reconciliation time, so a private save after a long idle period does not immediately force a full portable search. Missing/unavailable FTS and PostgreSQL use the same token normalization through a portable catalog-only fallback, cached for at most 30 seconds. That fallback does not require PostgreSQL extensions; a native PostgreSQL search index remains a deployment-specific optimization.

`docs/catalog_search_aliases.json` is an explicit ID-to-name mapping with `works` and `people` objects. Values are arrays of verified alternative titles/names. It starts empty: software work must not invent literary aliases or rewrite source titles. `CATALOG_SEARCH_ALIASES` and `CATALOG_SEARCH_INDEX` can override locations for isolated tests/deployments. Rebuilding is atomic and keeps the previous index if validation fails. The running worker's catalog edits and ordinary imports remain intact.

Catalog, author, library, history, shortlist, overlap and planner controls keep their committed query/page/filter/month state in the URL. Typing is debounced; it replaces the current query entry rather than creating a browser-history entry for every keystroke. Explicit filter and page changes create entries, and unrelated route parameters are preserved. Back/Forward restores query state and the previous scroll offset; scroll offsets are bounded, memory-only and contain no document text. Route content stays mounted across query changes so pending editor drafts are not discarded.

Navigation includes a skip link, current-page semantics, page-specific titles and heading focus after route changes. On phones the closed drawer is removed from keyboard navigation; the open drawer traps focus, supports Escape and restores focus to its trigger. Existing modal focus behavior is preserved. `navigation.tsx` supplies the reusable hooks; `browseState.ts` contains pure URL construction and validation.

Twenty-four backend search regressions passed against an isolated Django test database and temporary media directory. They cover targeted title/author/tag updates, relationship removals and clears, private/image edits, bulk changes and reverts, aliases, rollback/interruption, concurrent queue generations and bounded staleness. A 29 September isolated snapshot benchmark with 15,129 documents measured a full rebuild at 583 ms, one title update at 2.67 ms (one document), and unchanged-source reconciliation at 37.45 ms (25,683 narrow catalog/link rows checked; zero documents reconstructed or rewritten). These are local backend measurements, not browser latency or PostgreSQL measurements. Five URL-state regression cases passed in `frontend/tests/browseState.test.mjs`; the root integration check records final build/lint results. No browser automation or catalog research was performed.

## Bounded study reads

Classical study now opens with `part=summary`: completion, due dates and preferences are projected without transferring note/essay bodies or revision text. The full legacy state and text/private exports remain available. Panels request only their necessary record families through `part=records&family=…`: 24 current records per page, explicit Load more, and no automatic download of every page. Today loads journal sessions; recall loads recall records; the essay workshop loads essays and their commonplace evidence; modules and activity notebooks load their own records. Previously opened panels and drafts stay mounted.

Current record bodies omit earlier revisions/attempt text while retaining revision numbers and accurate history counts. Expanding history requests 12 prior versions at a time. Each page carries the profile revision, and loading pages from conflicting snapshots is rejected. Edits remain disabled until relevant record families are completely loaded; opening a partially loaded collection cannot silently overwrite a missing saved item. Refresh merges lightweight progress into retained state, then reloads the required record pages, preserving unsaved editor drafts. Late requests from an earlier refresh are ignored. Deltas update only changed paths and do not mark unseen families complete.

The existing server mutation adapter still reconstructs complete state under the account/profile locks to preserve cross-record validation and all earlier revisions. It writes only changed normalized records. Session journals retain their existing profile storage and are paginated when transmitted. No study migration or authoritative database change was required for these read-path improvements. Eight new study paging regressions plus five existing technical regressions passed in an isolated database; three frontend state-merge regressions passed. TypeScript and focused lint checks passed; browser verification remains for the owner.
